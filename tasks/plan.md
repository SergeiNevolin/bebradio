# План: Возврат режима «Караоке» для скачиваемых треков

Источник требований: `SPEC.md` (корень репозитория). Open Questions закрыты:
`--sub-langs "ru.*,en.*"` фиксирован; приоритет ручных субтитров над авто сохраняем;
разовый прогрев уже скачанных треков не делаем — ждём естественного TTL-цикла.

## Компоненты и зависимости

```
[T1 storage: разделить аудио/субтитры] ──┐
                                         ├──> [T3 media-service: captions с диска + новый эндпоинт]
[T2 download: флаги субтитров yt-dlp] ───┘            │
                                                     ▼
                                     [T4 backend: rename Captions → MediaCaptions(mediaID)]
                                                     │
                                                     ▼
                                     [T5 backend: handleGetLyrics берёт track.MediaID]
                                                     │
                                                     ▼
                                     [T6 верификация: комната, синхрон, зелёные тесты]
```

- **T1** и **T2** независимы (разные функции в `storage.py` и `providers/youtube.py`),
  можно делать параллельно. Оба — пререквизиты T3.
- **T3** нужен и `captions_path()` из T1, и наличие `.vtt` от T2.
- **T4** зависит только от контракта эндпоинта T3 (можно начинать по сигнатуре,
  не дожидаясь ручной проверки T3). **T5** — после T4.
- **T6** — после T5. Frontend не трогаем (контракт `api.getLyrics` неизменен),
  отдельной задачи по нему нет — только проверка зелёных тестов в T6.

## Порядок реализации

1. **T1 — `storage.py`: аудио и субтитры не путаются.** Сначала, потому что без
   этого добавление `.vtt` в `media_dir` (T2) ломает `is_ready()`/`path()` и чистку.
   Поведение снаружи не меняется — чистый рефактор + новый `captions_path()`.
2. **T2 — `download()`: `yt-dlp` пишет `.vtt`.** Параллельно с T1. Отдельно, потому
   что затрагивает только формирование аргументов и не зависит от T1.
3. **T3 — captions с диска.** `service.captions_from_disk()` + `GET
   /v1/media/{media_id}/captions`; удалить `/v1/captions` и
   `YouTubeProvider.captions()` (парсер `_parse_vtt` оставить — переиспользуется).
4. **T4 — backend rename.** `Captions(sourceURL, lang)` → `MediaCaptions(mediaID,
   lang)` в интерфейсе `MediaClient`, `client.go`, `usecase/media.go`, моках.
   Поведение `handleGetLyrics` пока прежнее — сборка и тесты зелёные.
5. **T5 — backend handler.** `handleGetLyrics` берёт `track.MediaID` вместо
   `track.SourceURL`. Форма JSON ручки `/api/rooms/:id/lyrics` неизменна.
6. **T6 — верификация.** Ручной прогон в комнате + проверка синхрона + все тест-сьюты
   и `typecheck` зелёные.

## Параллельно vs последовательно

- Параллельно: T1 ‖ T2.
- Последовательно: (T1, T2) → T3 → T4 → T5 → T6.
- Один разработчик: делать в порядке T1→T2→T3→T4→T5→T6, коммит после каждой.

## Риски и меры

| Риск | Мера |
|---|---|
| `yt-dlp` называет файл не `media_<hash>.<lang>.vtt`, а иначе (напр. `.ru-orig.vtt`, `.en.vtt`, двойное расширение) | T2: после `_run` заглянуть в реальные имена в `media_dir`; `captions_path()` в T1 глобит широко `media_<id>*.vtt` и берёт по префиксу языка, а не по точному имени. Тест на несколько вариантов имён. |
| Рассинхрон: таймкоды VTT от начала видео, а `bestaudio` короче/длиннее | T6: проверить на клипе с интро; если дрейф стабильный — зафиксировать как известное ограничение в SPEC, подстройку оставить на следующую итерацию (не расширять скоуп). |
| `download()` начинает падать, если субтитров нет и `yt-dlp` возвращает ненулевой код из-за `--write-subs` | T2: использовать флаги, не делающие отсутствие субтитров фатальным (`--write-auto-subs` не роняет загрузку); тест «нет субтитров → аудио всё равно готово, `ensure` == True». |
| `.part`/промежуточные файлы субтитров остаются в `media_dir` и попадают в отдачу | T1: `captions_path()` игнорирует `.part`; T6: глянуть содержимое `media_dir` после загрузки. |
| Ретро-треки без `.vtt` дают «нет текста» до TTL-эвикта | Принято в SPEC. T6: убедиться, что фолбэк-ветка (`status='empty'`) отрабатывает штатно, без ошибок в логах. |
| Изменение сигнатуры `MediaClient` ломает другие реализации/моки | T4: `grep` по `Captions(` во всём `backend/`; править моки в `internal/domain/repository/mocks.go` и все `*_test.go`. |

## Контрольные точки верификации

- После **T1**: `cd media-service && python -m pytest` — зелёно; новые тесты
  `test_storage.py` на `captions_path()` и на чистку `.vtt` вместе с аудио.
- После **T2**: `python -m pytest` — зелёно; тест в `test_provider.py` на наличие
  флагов субтитров в аргументах `yt-dlp` и на «нет субтитров → загрузка ок».
- После **T3**: `python -m pytest` — зелёно; `test_api.py`: 200+`cues` при наличии
  файла, 200+`[]` без файла, 400 на кривом `media_id`; `grep` подтверждает, что
  `/v1/captions` и `captions()` удалены.
- После **T4**: `cd backend && go build ./... && go test ./...` — зелёно;
  `grep -rn "\.Captions(" backend/` не находит старую сигнатуру с `sourceURL`.
- После **T5**: `cd backend && go test ./...` — зелёно; `handler_test.go`
  подтверждает вызов `MediaCaptions(track.MediaID, lang)` и прежнюю форму ответа.
- После **T6**: `npm run build && npm run typecheck && npm test` в `frontend/` —
  зелёно; ручной сценарий из SPEC «Testing Strategy» пройден; проверены
  Success Criteria 1–7 из `SPEC.md`.

## Оценка

Небольшая фича, ≤ 5 файлов на задачу. T1–T5 по одной фокус-сессии каждая,
T6 — короткая проверка. Ветка: `feature/karaoke-offline-captions` от `main`
(не текущая `feature/mashups-page-ui`).

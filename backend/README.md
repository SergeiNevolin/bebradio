# bebradio backend

Go-сервис синхронного прослушивания: HTTP API, WebSocket, который держит всех
слушателей комнаты в одном темпе, и фоновые циклы, двигающие очередь, когда
клиенты замолчали.

## Запуск

```bash
# нужен PostgreSQL и yt-dlp в PATH (плюс Node.js — он требуется самому yt-dlp)
export DATABASE_URL='postgres://postgres:postgres@localhost:5432/bebradio?sslmode=disable'
export SECRET_KEY='...'
go run ./cmd/bebradio
```

Схема БД применяется при каждом старте: все выражения идемпотентны, отдельного
шага миграции нет.

## Тесты

```bash
go test ./...                       # без БД: интеграционные тесты пропускаются
TEST_DATABASE_URL='postgres://...' go test -race ./...
```

`-race` здесь не формальность: состояние комнаты меняют соединение каждого
слушателя и два фоновых цикла одновременно.

## Структура

| Пакет | Ответственность |
| --- | --- |
| `cmd/bebradio` | Сборка зависимостей, HTTP-сервер, корректное завершение |
| `internal/domain` | Состояние комнаты и правила воспроизведения. Без ввода-вывода |
| `internal/room` | Живые комнаты: права доступа, сохранение, рассылка, авто-радио |
| `internal/users` | Регистрация, вход, профили |
| `internal/auth` | JWT двух видов и bcrypt |
| `internal/api` | HTTP-обработчики, middleware, WebSocket |
| `internal/hub` | Открытые WebSocket-соединения и рассылка по комнатам |
| `internal/store` | Порт персистентности: `postgres` для продакшена, `memory` для тестов |
| `internal/youtube` | Обёртка над yt-dlp: поиск, потоки, субтитры, похожие треки |

## Как это устроено

**Комната живёт в памяти.** Первый запрос поднимает её из БД, дальше все
слушатели работают с одним общим состоянием. Комнату, к которой полчаса никто не
подключался, фоновый цикл выгружает — иначе реестр только рос бы.

**Блокировки.** У каждой комнаты свой мьютекс, у реестра — отдельный; порядок
захвата всегда «реестр, затем комната». Главное правило: под блокировкой комнаты
не происходит ни одного сетевого вызова. Медленная работа делается в три шага —
прочитать нужное под блокировкой, сделать вызов без неё, снова взять блокировку и
применить результат к тому состоянию, которое к этому моменту есть. Один вызов
yt-dlp занимает десятки секунд, и удержание блокировки на это время остановило бы
всю комнату.

**Позиция трека не тикает на сервере.** Комната хранит точку синхронизации, а
текущая позиция вычисляется от неё при каждом чтении, поэтому все клиенты
получают один и тот же ответ.

**Ссылки на поток протухают.** yt-dlp отдаёт googlevideo-URL, живущий несколько
часов. Сервис перевыпускает ссылки текущего и следующего трека заранее, так что
переход в конце песни не ждёт сети.

**Два вида токенов.** Пользовательский удостоверяет аккаунт; токен доступа к
комнате подтверждает только знание её пароля и не действует ни в какой другой
комнате. Одно не принимается вместо другого ни в одну сторону.

## Конфигурация

Всё читается из окружения; у каждого параметра есть безопасное значение по
умолчанию. Небезопасное для продакшена (ключ подписи по умолчанию, `*` в CORS)
сервис сообщает предупреждением в логе при старте.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ADDR` | `:8000` | Адрес прослушивания |
| `DATABASE_URL` | `postgres://postgres:postgres@localhost:5432/bebradio` | DSN PostgreSQL. Строки вида `postgresql+asyncpg://` принимаются и приводятся к обычному виду |
| `SECRET_KEY` | ключ для разработки | Подпись JWT. **Обязателен в продакшене** |
| `CORS_ORIGINS` | `http://localhost:3000` | Разрешённые источники через запятую |
| `LOG_LEVEL` / `LOG_FORMAT` | `info` / `json` | Логирование (`text` удобнее локально) |
| `JWT_EXPIRE` | `72h` | Срок жизни токенов |
| `BCRYPT_COST` | `12` | Стоимость хеширования пароля |
| `MAX_CHAT_MESSAGES` | `100` | Сколько сообщений чата хранится в памяти и уходит в снимке |
| `STREAM_REFRESH_MARGIN` | `600s` | За сколько до истечения перевыпускать ссылку на поток |
| `AUTO_ADVANCE_INTERVAL` | `2s` | Период фонового цикла |
| `AUTO_ADVANCE_GRACE` | `2.5s` | Насколько позиция должна перевалить за длительность трека |
| `ADVANCE_DEDUP_WINDOW` | `1s` | Окно, в котором повторное переключение игнорируется |
| `RADIO_REFILL_AT` / `RADIO_BATCH` | `1` / `3` | Когда авто-радио добирает треки и сколько |
| `YTDLP_PATH` / `YTDLP_JS_RUNTIME` | `yt-dlp` / `node` | Путь к yt-dlp и JS-рантайм для плеера YouTube |
| `YTDLP_CONCURRENCY` | `4` | Сколько процессов yt-dlp может работать одновременно |
| `DB_MAX_CONNS` / `DB_MIN_CONNS` | `20` / `2` | Пул соединений |

Числовые интервалы принимаются и как длительность Go (`600ms`), и как число
секунд (`0.6`).

## Endpoints

`GET /health` — живость, `GET /ready` — живость плюс доступность БД. Балансировщик
должен выводить из ротации инстанс, не проходящий `/ready`, но не перезапускать
его: рестарт не вернёт базу.

Остальное — под `/api`, плюс `GET /ws/{roomID}` для живого соединения.
